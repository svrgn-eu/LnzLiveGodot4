<review_criteria>
Evaluate the target files against the following Godot-specific pillars:
1. **Scene & Node Architecture:**
   - Adherence to "Call down, signal up."
   - Proper decoupled composition vs. brittle hard-coded node paths (`get_node("../../../")` vs. `@export` NodePaths or `%UniqueNames`).
2. **GDScript Best Practices & Type Safety:**
   - Strict static typing usage (typed variables, typed arrays `Array[Type]`, return types `-> void`).
   - Proper lifecycle usage (`_init`, `_ready`, `_enter_tree`, `_process`, `_physics_process`, `_UnhandledInput`).
3. **Memory & Performance:**
   - Signal connection leaks, orphaned nodes (`queue_free()` vs. `free()`), or cyclic `RefCounted` / `Resource` references.
   - Heavy logic or allocations inside `_process` / `_physics_process` that could be event-driven or managed via `Timer` / `Tween`.
4. **State & Data Management:**
   - Proper separation of data (`Resource`) and logic (`Node`).
   - Safe usage of Autoloads/Singletons without creating tight global coupling.
5. **Edge Cases & Bugs:**
   - Null-reference risks (e.g., accessing nodes before `@onready` / `_ready`, race conditions during scene transitions).
</review_criteria>
